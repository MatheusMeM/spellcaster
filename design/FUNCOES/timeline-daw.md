Request from Matheus (2026-09-09): "Copy the usability of DAWs like Ableton or DaVinci Resolve, of how to make a good timeline system". This file reads both, line by line, and says what goes into our timeline (dmx/laser/fx tracks with keyframes, cues, markers, In/Out), with which gesture, and what already exists in the code.

The `timeline-ux` workstream is editing `timeline.js`, `canvaskit.js` and `index.html` right now; the "today" column describes what existed when this was written, and §4 assumes its base is done (fixed layout, wheel/Shift/Ctrl, loop in the engine, local undo, shortcuts from `SHORTCUTS.md`).

## 1. Objects and verbs

No new vocabulary. **Track** is the line of the `.spell` (`tracks[]`); **lane** is a drawn line — a track becomes one main lane (`spec.keys`) and one lane per animated parameter (`spec.scale`, `spec.rot`, `spec.x`…), `timeline.js:157-196`. **Keyframe** is Ableton's breakpoint: `[t, value, curve]`. **Marker** is a point on the ruler. **In/Out** is the pair that defines the working range (`SHORTCUTS.md`), and it is the one that plays the role of Ableton's *loop brace* — there is no second pair of handles. **Cue** is the track of type `cue` (`spellcore/engine/src/timeline.rs:354,369,393`): the cue list in time is already a track, not a new object.

Verbs added by the table in §2: **frame** (fit, detail, previous), **follow**, **nudge**, **lock**, **fold** (of the parameter lanes), **select time** (a range, not points).

## 3. Data model

Changes the `.spell`:

- **Marker with name and note** (item 26). Today the GUI writes `markers: [12.5, 40.0]` (numbers, `timeline.js:198-199,864`) and the engine already has a test with `markers: [{"t": 1.0, "name": "um"}]` (`spellcore/engine/tests/patch.rs:44-52`). Those are two formats in the same field, and neither of them is an error today because `show_patch` accepts any JSON (`edit.rs:825`). Recommendation: **object** `{t, name, note}`, with a number accepted on reading and converted (local migration, `FUNCOES/README.md §12`). No `color` (item 27).
- **`lock` per track**: `tracks[i].lock: true`. A boolean; the engine ignores it, as was already decided for lock. Recommendation: **it comes in**.
- **Color per track**: **does not come in as a field.** The color comes out of the `type` (item 31).
- **Track height and lane fold**: **do not go into the `.spell`.** That is window state, and `FUNCOES/README.md §12` forbids window state inside the show. They go to the GUI's `config.json`.
- **Loop**: **does not go into the `.spell`.** It is transport state. If one day it needs to survive closing, the place is `transport.loop` (the `transport` object already exists: `shows/medgrupo.spell`).

Does not change the `.spell`, it is UI only: follow, zoom presets, overview strip, nudge, duplicate, time selection, scrub snap, `Alt` releasing the grid, edge-scroll, dragging the marker, drawing a cue on the ruler.

It is not format, it is runtime: **track mute and solo must take effect in the Rust player** (item 30). `solo` remains "mute of the others" computed in the client (`DECISOES.md`, 09/09); only `mute` goes down into the engine.

The two format changes (marker as object; `lock`) and the two refusals (color per track; height/fold in the file) are in `design/DECISOES.md` as **awaiting vote**.

## 4. Implementation plan

Execution order. The base is the `timeline-ux` workstream (fixed layout, wheel/Shift/Ctrl, loop in the engine, local undo, shortcuts). Rule for the workstream that implements it: **every new rule comes in as a pure function exported in `TL`, and the mouse/key handler only calls it** — it is the only way for the `node --test` test to cover it without a DOM. The harness of `spellgui/web/test/timeline.test.js:13-28` needs two one-line adjustments: real `CK.near` and `CK.sel` (today they are `() => -1` and `() => ({})`), copied from `canvaskit.js:26-36,58-72`.

**P1**

1. **Follow** (item 4). `TL.follow(t, viewX, zoom, w, gutter)` → new `viewX`, or `null` if the playhead is inside the window; `frame()` applies it; `onDown`/`wheel`/`zoomAt` set `TL.followOff = true`, `TL.locate` and `TL.play` clear it. Test: playhead in the middle → `null`; playhead 1 px past the right edge → jumps one page (the new `viewX` leaves the playhead at the left margin); playhead before the left edge → comes back.
2. **Loop with the player** (item 5). `TL.loopWrap(t, inT, outT, loop)` → corrected `t`, used in the local `frame()` **and** in the player branch (today `timeline.js:390` returns before looking at the loop): with the engine, on crossing the Out it sends `locate(in)`. Test: `t > out` with loop → `in`; without loop → `t`; `out <= in` → `t` (never an infinite loop).
3. **`Alt` releases the grid, `Shift` fine-tunes** (items 11 and 12). `onMove` (`timeline.js:750-760`): `!p.shift` becomes `!p.alt`; `p.shift` now divides the vertical step by 10. A line and a half, with no test of its own — the snap behavior is already item 5 of the test list below.
4. **Nudge** (item 14). `TL.moveSel(dt)` → applies it in `TL.lanes` and returns the list of edits (`{k:"move", …}`) that goes to `commit`; `onKey` wires `,` / `.` / `Shift+,` / `Shift+.` with `dt = ±1/fps` and `±5/fps`. Test: build `TL.lanes` with two lanes by hand, select a keyframe, call `TL.moveSel(1/30)`, check the new `ts` and the returned `{k:"move", from, t}`; and check that `TL.ops` turns that into `key_del` + `key_set` (already covered by `timeline.test.js:45`).
5. **Snap on the scrub** (item 13). `onMove` of the `scrub` mode goes through `snapT`. Test: `TL.snaps = [0, 3, 10]`, `TL.snap = true`, `TL.k.view.zoom = 100`; `TL.snapT(3.02)` → `3`; `TL.snap = false` → `3.02`.
6. **`Shift+M` does not create a marker** (item 26). `onKey`: the `M` branch gains `&& !shift`, and `Shift+M` (and `M` over an existing marker) calls `TL.markerEdit(t)`. Along with it come `TL.markerT(m)` (accepts a number or `{t}`) and `TL.markerList(show)` (normalizes and sorts), used by `jumpMarker`, by the drawing and by the snap. Test: `TL.markerList({markers:[3, {t:1, name:"pico"}, 2]})` → sorted, three objects, `name` preserved; `TL.markerT(3)` → `3`.
7. **Mute taking effect in the player** (item 30). `spellcore/engine/src/timeline.rs`: a track with `"mute": true` does not write to the universes. Rust `#[test]` next to the ones that already exist in `timeline.rs:570-590`: two tracks on the same address, one muted, the frame comes out with the value of the unmuted one.

**P2**, in order: zoom presets with a way back (22) · fold the parameter lanes `U` (18) · track lock (32) · track height (19) · color per family (31) · marker with dialog and drag (26, 29) · cue on the ruler (36) · double-click creates a keyframe (16) · `Alt`+drag duplicates (15) · time selection and `Ctrl+L` on the selection (33, 6) · whole In–Out bar draggable (8) · overview strip (20) · edge-scroll (23) · grid in frames (9) · `Shift` fine-tuning the value (12) · J/K/L with rate in the engine (24).

Each one takes a test of the same shape (pure function + `assert`): `TL.zoomBack()` stores and returns the pair `{x, zoom}`; `TL.fold(li)` returns the list of visible lanes; `TL.locked(li)` is consulted by `delSelected`, `onMarquee` and `onMove`; `TL.laneColor(type)` returns the token; `TL.timeSel(r)` returns `{t0, t1, lanes}`.

**P3**: draw mode `B` (17) · `K+J`/`K+L` (25) · Inspector with a keyframe button (34) · clip trim (37).
